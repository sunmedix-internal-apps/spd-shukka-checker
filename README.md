# SPD出荷チェッカー

iPhone SafariとBluetoothバーコードリーダーを使い、オリコンラベル・SPDラベル・実商品のJAN／GS1-128を3点照合する静的Webアプリです。

## ローカル確認

ブラウザの保存機能と音声ファイルを正しく扱うため、`file://` で直接開かずローカルWebサーバーを使用します。

```powershell
python -m http.server 8000
```

起動後、Edgeで `http://localhost:8000/` を開きます。

1. 「マスター管理」でCP932の `ラベルマスタ.tsv` を選択します。
2. 「音声を有効化」を押します。
3. 「出荷チェック」でオリコンラベル（施設コード10桁＋部署コード10桁）を読み取ります。
4. SPDラベルQR（数字32桁）を読み取ります。この時点では仮受付で、件数は更新しません。
5. 商品外装のJANまたはGS1-128を読み取ります。一致した時点で1件を処理済にします。
6. バーコード照合できない商品は、商品待ち画面の `SKIP` を押すか、商品待ち中に専用バーコード `SPD-SKIP` を読み取ります。
7. 「社員コード待ち」になったら作業者の名札バーコードを読み取ります。社員コード取得後にSKIPが確定し、次のSPDラベル待ちへ進みます。
8. 「未読取一覧」で対象期間の残り、「読取履歴」でOK・SKIP・NGの実績を確認します。

PCからSKIP専用バーコードを印刷する場合は、「マスター管理」の一番下にある「SPD-SKIPバーコードを表示」を押し、プレビュー画面の「印刷」を使用します。A4用紙の上部に、バーコード幅40mm・高さ約14.97mm、外側余白7mmの切り取り用ラベルとして印刷します。バーコードは通常のCode128で、読取結果は `SPD-SKIP` です。GS1-128のAIやFNC1は含みません。SVGをアプリ内のJavaScriptで生成するため、外部ライブラリやCDNへ接続せず、オフラインでも表示できます。

`JANコード` は任意項目です。マスターにJANコードがない商品もSPDラベル受付後は商品待ちとなり、SKIP操作と作業者社員コードの読取が完了するまで処理済にしません。社員コード待ちでは次のバーコードをJAN／GS1ではなく社員コードとして受け付け、前後の空白だけを除いた文字列として先頭ゼロを保持します。社員マスタとの照合は行いません。JANコードに値が入っている場合は、照合可能な12桁または13桁の形式が必要です。

指定中の施設・部署について、対象期間の全ラベルがOKまたはSKIPで処理済になった場合は `complete.wav` を再生します。最後の正常照合では通常の成功音と重ねず、完了音だけを鳴らします。

音声の役割は、SPDラベル仮受付が `ok.wav`、商品JAN／GS1-128一致が `product-ok.wav`、全件完了が `complete.wav` です。商品照合成功音は3音上昇の短いチャイムで、既存成功音より達成感を持たせつつ完了音より控えめにしています。

実機リーダーがない場合は、「ローカルテスト用の手入力」を開いて同じ値を入力できます。

## 画面幅

表示領域が700px未満の場合は、従来どおりスマートフォン向けUIを全幅で表示します。700px以上のPCブラウザでは、同じ縦長UIを最大430pxで左右中央に表示します。端末種類の判定は行わず、画面幅だけで切り替えます。縦方向は固定しないため、内容量に応じて通常どおりスクロールできます。

PCの出荷チェック画面では、1366×768・ブラウザ倍率100%を目安に、待機・OK・NG・SKIPの各判定で「対象総数・処理済・未読取」まで見えるよう、ヘッダー、タブ、現在のオリコン、判定文字と商品詳細をコンパクト表示します。700px未満のスマートフォン表示には、このPC専用の圧縮を適用しません。

## データ保存

マスター、対象期間、現在部署、処理済ラベルキーはSafariの `localStorage`（ブラウザ内の小規模な保存領域）に保持します。OK・SKIP・NGの読取履歴は `IndexedDB`（履歴向けのブラウザ内データベース）へ分離して継続保存します。SKIP履歴には作業者社員コードを `employeeCode` という文字列項目で保存します。安全のため、商品照合待ちと社員コード待ちのSPDラベルはページ再起動後に復元しません。

新しいマスターを正常に取り込むと、以前のマスターに紐づく部署・処理済状態はリセットされ、「SPDラベル日付」の開始日・終了日は利用端末の当日に設定されます。過去の監査履歴は自動削除せず、「読取履歴」の管理欄から確認付きで削除します。取込に失敗した場合は、現在のマスターと対象期間を変更しません。

履歴画面ではSKIPした作業者社員コードを確認できます。「CSV出力」は「作業者社員コード」列を含むUTF-8 BOM付きCSVを作成し、iPhoneのWeb Share API（共有画面）を開きます。通常OK・NGと既存の旧履歴では同列は空欄です。共有画面からメールアプリを選択して添付送信できます。共有非対応ブラウザではCSVダウンロードへ切り替わります。社員コードを含むCSVは個人情報として適切に管理してください。

TSVは毎回、利用者がファイル選択画面から最新ファイルを選択します。SharePoint／OneDriveの保存済みパスから自動取得する処理やMicrosoft Graph APIは使用していません。

## GitHub Pages公開後の確認

- iPhone SafariでCP932のTSVを選択・復元できること
- BluetoothリーダーがHIDキーボードとして文字列とEnterを送れること
- 初回タップ後に正常音・警告音・完了音が鳴ること
- 商品違い後も同じSPDラベルの照合待ちが維持されること
- SKIPボタンと `SPD-SKIP` の社員コード待ち、SKIP取消、社員コード付き履歴、最後の1件をSKIPした場合の完了音
- PCのマスター管理画面でSKIP用バーコードを表示・印刷し、実機リーダーの読取結果が `SPD-SKIP` と完全一致すること
- CSV共有画面からメールアプリへCSVを渡せること
- 画面ロックやSafari再起動後の保存状態
- 実データで部署コードが複数施設に重複していないこと

個人情報・機密情報を含むTSVを公開リポジトリへ追加しないでください。

## iPhoneのホーム画面へ追加

GitHub Pagesへ配置したHTTPSのURLをSafariで開き、以下を行います。

1. Safari下部の共有ボタンを押します。
2. 「ホーム画面に追加」を選択します。
3. 表示名が `SPD出荷`、専用の箱＋チェックマークのアイコンになっていることを確認します。
4. 「追加」を押します。
5. ホーム画面のアイコンから起動します。

ホーム画面から起動した場合は、Safariのアドレスバーを表示しない独立したアプリ画面になります。主要なHTML・CSS・JavaScript・音声はService Worker（Webアプリのオフライン保存機能）で端末へ保存されます。

初回利用時は通信可能な状態で一度起動し、マスター取込と音声有効化を行ってください。iPhoneでアイコンや画面が更新されない場合は、既存のホーム画面アイコンを削除してSafariから追加し直してください。
